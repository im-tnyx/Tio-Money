# Tio Money — owner-selected pre-merge UI preview in Expo Go

## Manual fresh preview recovery — RFC #99 (unmerged)

A manual `codespaces_live` dispatch intentionally refreshes the selected exact PR source and restarts only a verified managed Metro process, even when the same SHA is already running. An automatic owner push still reuses a healthy managed PID and tunnel. If port 8081 belongs to an unowned process and no managed record exists, manual dispatch leaves it untouched and selects the first free port in 8082–8085. The selected port is stored with the managed PID/start ticks and used for listener, tunnel and source-map verification. An invalid record, foreign listener associated with a claimed managed process, dirty worktree or stale PR fails closed. A new port can create a new tunnel URL and may require reopening Expo Go; it does not cure a Codespace that never becomes Available or every Expo startup crash.

On startup failure, Actions prints a fixed category (port conflict, authentication, network, dependency or unknown) from the private bounded Metro log. Raw log lines, signed tunnel URLs and credentials are never printed. These source changes are review-only until independently checked and separately merged; no live operation is implied.

## Unified manual entry and incremental refresh (RFC #87)

After the scoped feature PR is independently reviewed and separately authorized for merge, select **Actions → TIO MONEY EXPO PR REVIEW → Run workflow** on `main`. Enter the positive integer PR number, select **Live Expo Go Preview** (`codespaces_live`, default) and `android`, `ios` or `all`. This is the only manual entry. The platform selection controls the post-sync Metro source probe; the same live tunnel serves Expo Go devices. The same workflow runs its Codespaces job automatically after the separate, secretless push signal. That signal has no manual entry. The EAS jobs run only on a manual dispatch for the selected EAS operation.

Eligibility remains owner-authored, same-repository and `main`-targeting, with exactly one open PR bearing `tio-preview`. Draft PRs qualify for Codespaces; EAS OTA/build require non-Draft. Owner pushes run through the secretless signal and trusted worker **only**, never EAS. The EAS runner is in `tio-money-eas-preview-trusted` and only its publishing step receives `EXPO_TOKEN`; the Codespaces runner is in `tio-money-codespaces-trusted` and only its remote-control steps receive `CODESPACES_TOKEN`. No secret set is inherited between jobs. The worker still checks main context, owner/first attempt, captured head/base SHA and immutable changed-path comparison, exact dedicated Codespace identity, label and source allowlist before remote control.

First activation verifies identity, starts the already selected Codespace if needed, imports the authenticated exact-SHA Git bundle into a clean dedicated detached checkout, installs locked dependencies only when missing or changed, starts managed Metro/tunnel and verifies health. On a subsequent eligible UI-only SHA it reuses an Available Codespace, validates the same bundle and clean checkout, switches to the exact revision without stopping a healthy Metro or tunnel, and probes Metro's generated Android/iOS source map against tracked Git source. A repeated dispatch of an unchanged healthy SHA is a no-op for sync/install/process lifecycle; source and tunnel health are checked again. A connected Expo Go app may Fast Refresh; reopen/reload the app manually if its displayed screen does not update. A source-map error fails the run; it is not a physical device refresh result. Native/config/tooling/dependency changes remain ineligible under the existing allowlist.

For recovery, inspect the **private** Codespace Metro log and process record. A stopped Codespace is started only after exact identity verification. An absent owned server starts normally; an unhealthy **verified owned** managed process may be restarted under the helper's lock. An invalid PID record, foreign port owner or dirty worktree fails closed: investigate manually without deleting user work or killing an unowned process. The exact known already-running HTTP 409 is followed by verified availability polling; other API errors fail. Rolling back this proposal means leaving the feature PR unmerged or an authorized ordinary revert; never force-reset the preview checkout. Live activation and Android/iPhone acceptance require separate owner authorization and physical testing. The source-map probe verifies tracked JS modules represented in Metro's generated bundle, not asset delivery, client HMR state or device display.

## Goal

For each new UI feature branch, keep its PR **unmerged** while previewing the exact current PR commit on Android Expo Go. Select the PR once, then each later **owner push** on that labeled branch wakes the chosen Codespace, syncs that exact SHA and refreshes its Expo tunnel. UI changes can be corrected on the same PR before an independent review/merge gate.

This path serves live **Expo Go Development Servers** via Metro. It **does not guarantee** that Expo Go's grey **Projects** card becomes clickable, that the server stays alive when Codespaces idle-stops, or that tapping Projects wakes a stopped Codespace. The trusted worker wakes on **push**, not phone taps. Published fingerprint-runtime EAS Updates in PR #5 are an entirely separate internal-build experience.

## Trust model

- GitHub Environment **`tio-money-codespaces-trusted`** is restricted to exact `main` per the owner's GitHub UI report. It holds `CODESPACES_TOKEN` (one secret reported). **Secret key/scopes and effective plan permission remain unverified by agent**. Do not reuse Tio-Workspace tokens or disclose values in chat/logs.
- The owner configures **two** non-secret Environment variables in `tio-money-codespaces-trusted`: `TIO_MONEY_PREVIEW_CODESPACE` (the name of one dedicated Codespace) and `TIO_MONEY_PREVIEW_CODESPACE_ID` (the exact immutable numeric ID shown by the GitHub Codespaces API). Independently name the **dedicated**, non-editing Codespace **`Tio Money PR Preview Only`** via its GitHub *display name*. The worker rejects anything except an API response matching all three, owner `im-tnyx` and repository `im-tnyx/Tio-Money` before start/SSH; it always rejects the known editing Codespace `automatic-orbit-jjxwq55wqr5gcj7gj`. A display name is an owner-applied purpose label, not a secret or a substitute for separating workspaces. No fallback. Use one small instance; compute billing applies when awake.
- The untrusted `tio-money-preview-push-signal.yml` runs on non-main pushes with **read-only permissions, no checkout, no secrets**. The Codespaces job in `tio-money-eas-pr-preview.yml` runs from trusted default `main` on a successful signal or on owner-only manual dispatch.
- Every worker run requires `main` context, repository/push actor `im-tnyx`, an **open owner-authored, repository-local PR targeting main**, exact current branch and SHA, the `tio-preview` label, and **exactly one** labeled open PR globally. Draft PRs are allowed for testing. A changed or stale SHA fails closed.
- **P2 immutable-scope gate (2026-11-20):** The worker captures exact head and base commit SHAs before reviewing files, uses GitHub's immutable `compare/{base_sha}...{head_sha}` endpoint instead of the moving `/pulls/{number}/files` list, validates response commit identities, file count and renamed original paths, and re-fetches PR metadata to reject a changed head/base before any Codespaces start or SSH. Regression fixtures include a PR head advance between the two reads. The trusted default-main checkout runs the validator and uses a reviewed immutable `actions/checkout` commit SHA. Manual dispatch also denies a non-owner retry actor or reruns. These checks do **not** authorize a privileged execution and do not replace independent security review.
- Only **UI/source-only PRs** are eligible. Changed paths must be in `src/`, `assets/`, `tests/`, `docs/`, `.ai/` or the explicitly allowed root Markdown files. No native directories, `app.json`, npm dependency manifests, action scripts/workflows, devcontainer or secrets/config changes from the PR are accepted by this worker. Review and test those changes separately.
- Actions checks out only the **trusted main SHA** to obtain `.github/scripts/sync-pr-codespaces-preview.sh` and sends it by SSH to the selected Codespace. PR files are **never checked out/executed on the privileged Actions runner**. Inside the Codespace, verify exact origin, clean worktree and fetched SHA, stop only the managed Expo server, switch to detached immutable HEAD without force/reset, then reuse/restart the Expo Go signed tunnel. No automatic creation, merge, publish, production release or changes to the unrelated `@tnyx-23/tnyx`.
- The selected PR's JavaScript runs inside the preview Codespace and is therefore **owner-authored only**. A PR containing malicious JS/Metro config could still affect its **Codespace-local** credentials. Do not load untrusted forks or sensitive finance fixtures. Review requested platform changes separately.

## Failure modes and recovery

| Situation | Expected safe result |
|---|---|
| Missing/wrong label or no owner push PR | No automatic preview switch |
| More than one labeled open PR | Worker refuses preview |
| PR is forked, non-owner, closed, or not targeting main | Refused |
| New PR changes native/tooling/dependencies | Refused; use independent native/device review instead |
| Changed/stale push SHA or wrong Codespace | Refused |
| Selected editing Codespace, missing/mismatched numeric ID, wrong owner/repo or missing exact `Tio Money PR Preview Only` display label | Refused **before Codespace start/SSH**; provision a separate preview-only target |
| Selected Codespace has uncommitted/untracked work | Refused; never stash/reset/force it |
| Incorrect remote or unexpected fetched SHA | Refused |
| No SSHD yet / Codespace suspended / no login | Run fails visibly; owner remedies Codespace and retries |
| Expo Go Projects card still grey | NOT_VERIFIED / unaffected; test Development Servers and investigate account/Expo publication separately |

**Testing gates:** source tests in `tests/preview/pr-codespaces-workflow.test.mjs`, all `npm run check` / `npm run preview:test`, CI and manual Android owner acceptance after a trusted authorized workflow dispatch. iPhone can be tested later. The workflow is intentionally not operational from a feature branch; it must be reviewed and merged into `main` with owner-specific merge permission and secrets/protections still intact.

# PR #88 review correction — trusted preflight compatibility

The trusted-main Codespaces worker now streams a read-only ownership/port preflight over SSH before its same-SHA probe and again just before source sync. This gate does not call `--preflight` from the selected PR checkout, so an older eligible source-only PR whose starter predates that option can reuse a healthy owned Metro/tunnel. The preflight rejects a missing ownership record with an occupied port, malformed/stale/foreign PID records, symlinks and unsafe record ownership/mode. The clean worktree and exact bundle/SHA gates still apply. A source-only revision can retain the existing PID and tunnel URL; an old starter may fail closed on unhealthy Metro until a reviewed starter update is available. Never delete an uncertain PID record or terminate an unowned process to bypass this gate.

This is a static review correction in Draft PR #88. Live Codespace execution, Android/iPhone Fast Refresh and tunnel continuity still require separately authorized manual acceptance.

### Served revision verification

Each requested platform receives its own result. PASS requires at least one affected application module in its served graph and a match for all application modules examined. An unchanged-only graph is UNVERIFIED. Lazy or platform-specific modules can be absent from a graph. A stale module, malformed reply, redirect, or unverifiable listener fails the probe. Inconclusive verification leaves the synchronized checkout and healthy Metro/tunnel session running.

The trusted worker rechecks the selected PR and approved source scope before privileged work. GitHub eligibility and the downstream operation are separate requests. A later GitHub state change cannot replace the immutable SHA being used.

An eligible owner push synchronizes the authenticated exact commit before Metro delivers any Fast Refresh event. The trusted worker preserves the managed Metro PID and tunnel for compatible runtime inputs and verifies both after synchronization. A dependency or startup-input change requires verified-owned recovery before runtime files change. A legacy record without a runtime fingerprint requires the same recovery. A stale selection or unverified listener fails closed. If the tunnel cannot be confirmed after a compatible sync, the worker reports failure and leaves the existing process in place.
